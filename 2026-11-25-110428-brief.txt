## README.md
# ollama-repl

- **Dedicated HTTP client**: `lib/ollama-client.js` uses `fetch()` via `LWSContext`, new connection per prompt.  
- **Token streaming**: `chatStream()` reads real `ReadableStream`, default; `--no-stream` disables.  
- **File detection**: Paths/globs auto-resolved (`lib/file-refs.js`, `lib/match.js`); dir `/` loads up to 4 files, top-level first, newest-first per depth. Specific files trigger import extraction (`lib/imports.js`).  
- **File exchange**: All file in/out tracked (`lib/file-exchange.js`); diffs saved to `diffs/NNN-name.diff`, revertable via `patch -R`.  
- **File output**: `File: path` blocks written to project; other code blocks saved as `<model>-output-N.ext`, numbered to avoid collision.  
- **Project awareness**: `LIST:/READ:/RUN:` auto-executed if model asks; `RUN:` requires approval via `ChatREPL#confirm()`.  
- **Startup scan**: Shallow top-level listing (JS/C/HTML/CSS/MD, `.gitignore` filtered) + `README.md`, `CMakeLists.txt`. `/reset` keeps scan; `/clear` removes it.  
- **Session persistence**: `session.json` saved after each turn; resumes on startup if exists; `/clear` discards.  
- **QuickJS/qjs-modules**: `quickjs.h`, `qjs-modules` built-ins referenced; `LIST:/READ:` access sibling projects.  
- **Real editing**: qjs-modules' `repl` module enables arrow history, `^R`, Tab completion (project paths), plain text input.  
- **Session log**: `session.log` timestamps all prompts, replies, tools, file writes (read-only).  
- **Thinking indicator**: Animated spinner (Unicode glyphs), nerd jokes by phase; capped at `DEFAULT_TIMEOUT_SECS` (15min).  
- **Direct clients**: `lib/ollama-client.js`, `lib/gemini-client.js`, `lib/openai-client.js` support `tools: [{ name, description, parameters }]` with `chat()`/`chatStream()` returning `{ content, toolCalls? }`.  

Open tasks: Tool calling via native APIs (not reply parsing), full recursive file scan, diff auto-merge.

## doc/API.md
# Message/tool-use format rewrite

## Problem  
`GeminiClient#chat()`/`#chatStream()` and `OllamaClient` use flat arrays of `{ role, content }` turns. Ollama's shape lacks support for tool use; Gemini's API supports tool calls but only via `functionCall` and `functionResponse` parts in `contents`, not a dedicated role.

## Research: API tool use  
**Gemini `generateContent`**:  
- `Content.role`: only `"user"` or `"model"`; no `"function"` role.  
- `parts`: `{ text }`, `{ functionCall: { name, args } }` in model-role turn, `{ functionResponse: { name, response: object } }` in user-role turn.  
- `tools`: `{ functionDeclarations: [{ name, description, parameters }] }` (OpenAPI JSON Schema).  
- `toolConfig.functionCallingConfig.mode`: `'AUTO'` (default), `'ANY'`, `'NONE'`.  
- `functionCall` parts arrive whole in streaming events.  

**Ollama `/api/chat`**:  
- `tools`: `{ type: 'function', function: { name, description, parameters } }`.  
- Tool call reply: `message.tool_calls: [{ function: { name, arguments } }]`.  
- Tool result: `{ role: 'tool', content: string, tool_name: string }`.  
- No `tool_choice` knob; always behaves like `'AUTO'`.  
- `tool_calls` appear whole in streaming NDJSON chunks.  

## Design: Extended message format  
Callers build array with:  
- Plain turn: `{ role: 'system'|'user'|'assistant', content: string }`  
- Assistant tool request: `{ role: 'assistant', content?: string, toolCalls: [{ id, name, args }] }`  
- Tool result: `{ role: 'tool', name: string, content: string | object, toolCallId?: string }`  

- `toolCalls.id`: synthesized as `${name}#${index}`; never sent over wire.  
- `toolCalls.thoughtSignature`: for Gemini 3 models; must be echoed back in same part; stored and sent.  
- `tool.content`: string (common) or object; `GeminiClient` wraps as `{ result: content }`, `OllamaClient` strings it.  

New options:  
- `tools: [{ name, description, parameters }]` – passed to wire format.  
- `toolChoice: 'auto' | 'any' | 'none'` – maps to Gemini; Ollama ignores.  

Return value:  
```js
{ content: string, toolCalls?: [{ id, name, args }] }
```  
`toolCalls` only if model requested a call. `chatStream()`'s `onToken` unchanged – tool calls not streamed.  

## Out of Scope  
- Multimodal parts (`inlineData`, `fileData`) – not needed for text-only workflow.  
- Real tool-calling

## 0. Example prompts

## 1. What the model needs to know  
1. JSValue lifecycle: refcounted; JSValueConst = borrowed; returned values must be freed with JS_FreeValue(ctx,v) or JS_FreeValueRT (in finalizer).  
2. Exceptions are values: JS_EXCEPTION is a JSValue returned on failure; every call must check and propagate (goto fail).  
3. O

## FILENAME  
void *JS_GetOpaque(JSValueConst obj, JSClassID class_id);  
void *JS_GetOpaque2(JSContext *ctx, JSValueConst obj, JSClassID class_id);  

Allocate class ID once (module init). Register with JS_NewClass.  
Constructor: JS_NewObjectProtoClass + JS_SetOpaque.  
Getters/setters: JS_GetOpaque2 (throws on wrong class), not JS_GetOpaque.

## FILENAME  
JSValue JS_NewArrayBuffer(JSContext *ctx, uint8_t *buf, size_t len,  
                          JSFreeArrayBufferDataFunc *free_func, void *opaque,  
                          JS_BOOL is_shared);  
uint8_t *JS_GetArrayBuffer(JSContext *ctx, size_t *psize, JSValueConst obj);  

JS_GetArrayBuffer returns pointer into buffer — don’t free it.  
Buffer freed by object via free_func.  
To return owned buffer: allocate with js_malloc, fill, then:  
JS_NewArrayBuffer(ctx, buf, actual_len, free_func, NULL, FALSE)  
with free_func calling js_free_rt.  
Pass actual used length, not allocated bound.

## FILENAME  
JSValue JS_NewBool(JSContext *ctx, JS_BOOL val);  
JSValue JS_NewInt32(JSContext *ctx, int32_t val);  
JSValue JS_NewUint32(JSContext *ctx, uint32_t val);  
JSValue JS_NewFloat64(JSContext *ctx, double d);  
int JS_ToInt32(JSContext *ctx, int32_t *pres, JSValueConst val);  
int JS_ToInt64(JSContext *ctx, int64_t *pres, JSValueConst val);  

JSValueConst in args = borrowed, don’t free.  
JS_ToInt32/ToInt64 return -1 on failure; check return, not just *pres.

## FILENAME  
JSValue JS_ThrowTypeError(JSContext *ctx, const char *fmt, ...);  
JSValue JS_ThrowRangeError(JSContext *ctx, const char *fmt, ...);  
JSValue JS_ThrowInternalError(JSContext *ctx, const char *fmt, ...);  
JS_BOOL JS_IsException(JSValueConst v);  
void JS_FreeValue(JSContext *ctx, JSValue v);  

No C try/catch. Functions must call JS_Throw* on failure.  
Check JS_IsException(v) and propagate.  
Every JSValue returned or stored must be freed via JS_FreeValue or JS_FreeValueRT.

## FILENAME  
void *js_malloc(JSContext *ctx, size_t size);  
void *js_mallocz(JSContext *ctx, size_t size);  
void js_free(JSContext *ctx, void *ptr);  
void js_free_rt(JSRuntime *rt, void *ptr);  

js_malloc/js_free: context-bound.  
js_free_rt: runtime-bound, used in finalizers.  
Never mix with libc malloc/free.

## FILENAME  
JSClassID JS_NewClassID(JSClassID *pclass_id);  
int JS_NewClass(JSRuntime *rt, JSClassID class_id, const JSClassDef *class_def);  

Same pattern: JS_NewClassID, JS_NewClass, JS_SetOpaque, finalizer.  
Finalizer uses js_free_rt.

## FILENAME  
#define JS_CFUNC_DEF(name, length, func1) { ... }  
#define JS_CGETSET_MAGIC_DEF(name, f)  

Functions with getter, fsetter, magic) { ... } are registered via JS_SetPropertyFunctionList.
