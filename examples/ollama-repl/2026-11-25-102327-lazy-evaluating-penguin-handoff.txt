**Instructions for Reader:**

You are now responsible for continuing the development and implementation of the ollama-repl project. This document provides all the necessary technical details, architecture, design decisions, open issues, and implementation requirements that you must use to proceed with your work.

Before making any changes or implementing new features, you must adhere to the following principles:

1. **Scope of Work**: You are only authorized to work on the ollama-repl project as defined in the original project brief and the files provided. Do not introduce new features or modify existing functionality without explicit approval.

2. **File System Structure**: The project is organized into the following directories:
   - `doc/`: Contains architectural, API, demo, and model documentation.
   - `lib/`: Contains source code for core components and modules.
   - `reference/`: Contains reference materials such as the quickjs-binding-api.md.
   - `examples/`: Contains example C files (e.g., fib.c, point.c) used for binding demonstrations.
   - `TODO.md`: Contains open issues and unresolved tasks.
   - `README.md`: Contains high-level project overview and usage instructions.

3. **Core Architecture**: The system is built as a single QuickJS process with one event loop. There are no background workers or parallel processes. All functionality is implemented in a single thread.

4. **Component Responsibilities**:
   - `repl.js`: Main entry point and control flow.
   - `ctl.js`: Handles control commands and interactions.
   - `lib/*-client.js`: Provides native API bindings for OpenAI, Ollama, Gemini, and freellm.
   - `turn engine`: Manages tool requests, modes, repair, handoff, and failover logic.
   - `gateway`: Handles provider availability, rating, and exploration.
   - `TUI (Terminal User Interface)`: Includes components like tui.js, chat-repl.js, pager.js, look.js, ansi.js, usage-stats.js, net-pane.js, events.js, markdown.js, rawcolor.js, quips.js, and session-name.js.
   - `Sessions`: Managed through session-cache.js, session-store.js, session-log.js, config.js, persist.js, file-refs.js, file-blocks.js, file-exchange.js, sent-files.js, project-brief.js, reference-files.js, binding-context.js, imports.js, skills.js, match.js, paths.js, run-command.js, control-socket.js, and peer.js.

5. **Failover Strategy**: The system implements provider fallback and skip recovery. If a provider fails, the system attempts to use an alternative provider. Recovery is skipped if the failure is not critical.

12. **Signal Flow**:

13. **Key Functions and Parameters**:

    - `ctl.js`: Handles control commands like /reset, /clear.

14. **Error Handling**:
    - Silent gap > timeoutSecs → "Connection closed: timeout" error.
    - Mid-stream Ctrl-C → failure in tool execution.
    - No token meta in Ollama/Gemini responses → missing metadata.

15. **Memory Management**:
    - JSValue lifecycle: Free with JS_FreeValue/RT.
    - Exceptions are treated as values (JS_EXCEPTION).
    - Opaque class binding uses JSClassID and finalizer.
    - Memory management uses js_malloc/free vs js_free_rt.
    - ArrayBuffer is used for in/out data.
