#LWSVhost

A virtual host attached to an LWSContext. Implemented in lws-vhost.c. Most users do not need this — the default vhost is created from the context's vhostName property. Use LWSVhost when you need additional listeners, separate TLS certificates per hostname, or to attach a vhost to a different protocol set.

#Construction

const vh = new LWSVhost(ctx, info);

ctx is an LWSContext. info is the same shape as LWSContext's constructor info — every supported property (port, mounts, protocols, TLS, etc.) is forwarded to lws_create_vhost().

Throws TypeError if the first argument is not an LWSContext.

The constructor stashes the original info object on the resulting vhost as a configurable info property, mirroring LWSContext.

#Lifecycle

The finaliser calls lws_vhost_destroy() (if not already destroyed) and frees the stashed context_creation_info. As with LWSContext, callbacks may fire during construction because lws_create_vhost() is called last.

destroy() additionally drops a self-reference the vhost holds on its own JS wrapper (info.user), so calling it explicitly — rather than relying on the finalizer — is what actually makes the wrapper collectible again afterward.

#Looking up vhosts

From the context:

const vh = ctx.getVhostByName('admin.example.com');

From a LWSSocket:

function onEstablished(wsi) {
  console.log('vhost', wsi.vhost.name);
}
